# INPAY 代付订单凭证发送流程

## 核心原则

商户索要代付订单凭证时，必须先从 INPAY 后台查询并回读对应订单真实信息；只有订单存在且关键信息匹配时，才整理/截图凭证给商户。不要凭商户截图、口头描述或历史记忆生成凭证。

## 何时使用

- 商户说：要代付凭证、付款凭证、transfer proof、payout receipt、订单截图、成功截图。
- 商户直接发订单号并说：`给下凭证`、`发凭证`、`凭证`、`proof`、`receipt`、`screenshot`。
  - 例如：`KKB2607301807532377853828 给下凭证`。
  - 这类“订单号 + 凭证请求”必须触发本流程，不要当成普通聊天回复。
- 主人要求：查某笔代付订单并发商户凭证。
- 已知任一定位信息：平台订单号、Out Trade No、商户订单号、收款账号/手机号、金额、商户号、时间范围。

## 标准流程

1. **确认查询线索**
   - 优先使用：订单号 / Out Trade No / 商户订单号。
   - 若只有金额、手机号、时间，必须限定商户和时间范围，避免误发他人订单。

2. **后台查询订单**
   - 进入 INPAY 后台代付订单查询页面或可用只读接口/数据库查询。
   - 用订单号精确查询；如果没有订单号，用商户号 + 金额 + 收款账号 + 时间范围组合筛选。
   - 回读以下字段：
     - Country / 国家
     - Transfer to / 收款账号或手机号
     - Out Trade No / 外部交易号
     - Total Fee / 金额
     - Create Time / 创建时间
     - Status / 状态
     - Customer Name / 收款人姓名（如后台有）
     - Merchant / 商户号与商户名（用于内部核对，通常不放给商户凭证）

3. **判断能否发送凭证**
   - 可以发送：订单存在，商户归属匹配，金额/账号/订单号匹配，状态为成功或后台明确展示可作为凭证的最终状态。
   - 不可发送：查不到订单、商户归属不一致、金额或账号不一致、状态未成功/处理中/失败、疑似重复候选未唯一确定。

4. **生成/截取凭证**
   - 优先使用后台真实详情页截图，隐藏无关后台导航、内部备注、通道成本、API 密钥、风控备注、系统内部 ID 等敏感信息。
   - 截图内容建议保留类似：

```text
Payout Transfer Details

Country        CotedIvoire
Transfer to    0759232813
Out Trade No   KKB2607301807532377853828
Total Fee      1170.00
Create Time    2026-07-30 10:07:54
Status         Payout Success
Customer Name  Eze Ezechiel
```

   - 如无法截图，可按同样字段制作简洁文字凭证；但必须注明“后台查询结果”。

5. **发送前检查**
   - 核对凭证中的手机号/账号、金额、订单号、状态是否与后台一致。
   - 如果触发消息包含订单号（如 `KKB2607301807532377853828 给下凭证`），发送的凭证必须明确引用/展示这个触发订单号，优先放在 `Out Trade No` 字段；不要只发一张无法对应订单号的泛化截图。
   - 确认没有泄露：后台登录地址、操作员账号、内部通道名、手续费成本、供应商流水、密钥、Cookie、Token、私有备注。
   - 对外发送前若需要代表客服发消息，先给主人草稿/截图预览；除非主人明确授权可直接发送。

6. **商户回复口径**
   - 成功订单：
     - `您好，已为您核实该笔代付订单，后台显示已成功，凭证如下，请查收。`
   - 查不到订单：
     - `您好，目前按您提供的信息暂未查询到对应代付订单，请补充平台订单号/商户订单号/收款账号/金额/创建时间，我们继续核实。`
   - 状态非成功：
     - `您好，已查询到该笔订单，目前后台状态为【{状态}】，暂不能作为成功付款凭证；我们会继续跟进状态变化。`
   - 信息不匹配：
     - `您好，按当前信息查询到的订单与您提供的金额/账号/订单号不完全一致，为避免误发凭证，请再确认订单号或收款信息。`

## 关键安全边界

- 不为未成功订单伪造成成功凭证。
- 不跨商户发送订单详情。
- 不把内部成本、通道、供应商、后台备注、风控标记发给商户。
- 不用历史截图复用成新凭证。
- 不把“查到类似订单”当成“确认对应订单”。必须唯一匹配。

## 验证清单

对外发送或交给主人前，报告/自检：

- 订单是否唯一匹配：是/否
- 商户归属是否匹配：是/否
- 金额和账号是否一致：是/否
- 状态是否可作为凭证：是/否，状态=...
- 凭证是否已遮挡敏感信息：是/否
- 发送对象：主人预览 / 已授权商户

## 常见坑点

| 错误做法 | 正确做法 |
|---|---|
| 只看商户提供的截图就回复“成功” | 必须后台查询并回读 |
| 只有金额就截图发送 | 必须用商户、账号、时间等组合唯一定位 |
| 把后台完整页面发出去 | 只保留商户可见凭证字段，遮挡内部信息 |
| 处理中订单发成功凭证 | 如实告知当前状态，不能伪造成成功 |
| 候选订单多个时选一个最像的 | 要求补充信息或继续核查，直到唯一匹配 |
